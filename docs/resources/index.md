### Requirements Checklist

Use this to verify you have extracted all requirements from a client brief.

- [ ] Business goals identified
- [ ] Target audience defined
- [ ] Functional requirements listed
- [ ] Content requirements listed
- [ ] Design requirements listed
- [ ] Technical requirements listed
- [ ] Constraints documented
- [ ] Assumptions documented
- [ ] Out-of-scope items identified

See Module 3, Chapter 09 and the [First Freelance Project](../projects/first-freelance-project) for examples.

### Freelance Proposal Checklist

Use this when writing a proposal for a potential client.

- [ ] Client problem restated in your own words
- [ ] Proposed solution described clearly
- [ ] Scope of work defined (what is included)
- [ ] What is NOT included stated explicitly
- [ ] Timeline with milestones
- [ ] Total price and payment terms
- [ ] Revision policy stated
- [ ] Your relevant experience mentioned
- [ ] Next steps clearly stated

See Module 1, Chapter 03 for guidance on writing proposals.

### Project Acceptance Checklist

Use this before delivering a project to a client.

- [ ] All specification requirements implemented
- [ ] Responsive design tested on mobile, tablet, and desktop
- [ ] All links work correctly
- [ ] No browser console errors
- [ ] HTML validates without errors
- [ ] CSS works as expected
- [ ] JavaScript functions correctly
- [ ] Git repository has clean commit history
- [ ] README.md is complete
- [ ] Project is deployed and live URL is tested
- [ ] Client delivery message is written
- [ ] Portfolio case study is prepared

See the [First Freelance Project](../projects/first-freelance-project) for a complete example.

### AI-Generated Code Review Checklist

Use this every time you accept code from an AI coding agent.

- [ ] Code solves the stated problem
- [ ] Code follows project conventions
- [ ] No security vulnerabilities introduced
- [ ] Edge cases are handled
- [ ] Code is maintainable and readable
- [ ] No unnecessary dependencies added
- [ ] No files outside scope were modified
- [ ] You can explain what every line does
- [ ] Tests (if any) pass
- [ ] No unexpected behavior

See Module 2, Chapter 02 and Module 2, Chapter 05 for guidance on reviewing AI output.

### Client Delivery Checklist

Use this when delivering a completed project.

- [ ] Project is complete per the specification
- [ ] Live URL is tested and working
- [ ] Repository is pushed to GitHub
- [ ] README.md describes the project
- [ ] Delivery message includes: live URL, repository URL, what was delivered, any limitations
- [ ] Next steps are clearly stated
- [ ] Follow-up timeline is mentioned

See the [First Freelance Project](../projects/first-freelance-project) for a delivery message template.
